# Trippy — Settled Decisions

Owner decisions that any coding agent (Claude Code, Codex, or otherwise) must respect and must not re-litigate.

**Why this file exists.** Agent memory stores are per-tool and per-machine. When one agent settles something and records it only in its own memory, the next agent — a different tool, or the same tool on a different machine — cannot see it and will re-propose work that is already done or already declined. This file is in git, so every agent reads the same truth.

**How this file relates to code markers.** Decisions attached to specific behaviour are marked `D-<plan>-<n>` in the code they govern (see "Settled Decisions" in `docs/ENGINEERING.md`). Those get **one line here plus a pointer** — the reasoning stays next to the code, where it cannot drift. Decisions with **no single code home** — service tiers, quotas, cross-cutting rulings — keep their full reasoning here, because this file is their only home.

**How to use it.** Read before proposing changes to a paid provider, a resolver strategy, or anything marked CLOSED. Append when a session settles something durable. Never delete an entry — supersede it and mark the old one SUPERSEDED.

### Unsplash API tier — CLOSED

**2026-07-28, owner.** Production tier is **granted at 1,000 requests/hour**. This is no longer a pending application or a constraint to design around. Do not re-propose applying for production access, and do not add rate-limit workarounds premised on the demo tier.

Standing constraints (how it works, not a decision): a single app-wide key is shared with agent diagnostics; each photo action costs a fetch; a throttled fetch leaves the photo `NULL`, recoverable via `backfillTripPhotos`.

The tier itself is an account fact with no code home, so it stays here — but the "no demo-tier workarounds" half of the ruling *does* govern code, and is marked above `search()` in `backend/src/services/unsplash.js`.

### Discovery catalogue — no rebuild

**2026-07-26 → 2026-07-28, Plan 26.** The catalogue is repaired incrementally, never rebuilt. The verified corpus is large (880+ active verified rows) and a rebuild would spend real provider money to regress it. Repair work is bounded and idempotent.

**2026-09-15, owner.** A future Trippy MCP is a hosted, client-independent Trippy feature developed in this repository. ### Backend unit suite makes no network calls

**2026-10-19, set while closing the Plan 34 W2 finding.** `npm test` in `backend/` cannot reach an external host. `backend/vitest.workspace.js` splits the suite into two projects. The `unit` project loads `backend/tests/setup/noNetwork.js`, which replaces `globalThis.fetch` with a guard: loopback (`localhost`, `127.0.0.1`, `[::1]`) passes, for the auth and MCP tests that drive their own in-process server, and every other URL is rejected **and recorded**, failing the test in `afterEach` even when the code under test caught the error. The recording matters because provider services fall back by design; the resolver turns a Nominatim failure into `unresolved` and the photo path logs and moves on, so an error alone would pass silently. Every paid provider goes through that global `fetch`. That includes the Anthropic SDK, which captures `globalThis.fetch` when its client is built (verified with a real `messages.create` hitting the guard). The `live` project (`tests/live`, `LIVE_ANTHROPIC=1`) is the one place real calls are allowed, and it does not load the guard.

How to stub a provider in a unit test: at the service boundary (`vi.spyOn(unsplashService, 'selectPhoto')`, `vi.spyOn(claudeService, 'generatePhotoDescriptor')`), or with a provider-shaped `vi.spyOn(globalThis, 'fetch').mockResolvedValue(...)` scoped to the test, as `tests/locationIntegration.test.js` does. Never `mockRejectedValue` on `fetch` as a "no network" marker, because the service swallows the rejection and the guard never sees the call. That is how `collaboration.test.js` kept making three Unsplash searches after its first fix. Never raise a timeout to make a provider call fit.

The census when the guard landed: one external caller, `importer.test.js` (a live Nominatim lookup for a confirmed flight's airport stop), plus the three Unsplash searches above. Both are fixed. Not done on purpose: `config.js` still loads the real `backend/.env` keys under `NODE_ENV=test`. The guard sits at the network boundary because the live suite needs those keys, and stripping them would quietly change which branches unit tests take.

**Trip-scope pre-warm is stubbed suite-wide (Plan 35 W4, 2026-10-20).** `createTrip` and the chip save now start background Discovery generations (D-35-3), and most test files create trips with country-coded destinations to test something else. Unstubbed, that fired about 300 detached generations across the suite. `backend/tests/setup/noDiscoveryPrewarm.js` loads for the `unit` project beside the network guard and replaces only `prewarmTripScopes` with a no-op; the kick that the co-pilot's search uses stays real. A test of the pre-warm opts back in with `vi.unmock('../src/services/discoveryPrewarm.js')`, as `tests/discoveryPrewarm.test.js` does.
